## 1. Design principles <a href="#section-001" id="section-001"></a>

1. **Correctness before performance**: use a NumPy prototype in the first phase to validate the algorithmic feedback loop.
2. **Pluggable core policies**: error estimation, splitting policies, and stability projection should all be replaceable.
3. **Traceable dynamic graphs**: record lineage for every node split, pruning operation, and isolation operation.
4. **Migration to deep-learning frameworks**: design data structures to support migration to PyTorch / PyG.
5. **Strict tests of key invariants**: especially adjacency-matrix dimensions, symmetry, isolation of old nodes, and feature norms.

## 3. Core data structures <a href="#section-003" id="section-003"></a>

### 3.1 `GraphState` <a href="#section-004" id="section-004"></a>

Responsibility: store the current dynamic graph, node features, tree structures, and lineage.

Suggested fields:

```text
GraphState
  x: np.ndarray                    # shape: [num_nodes, feature_dim]
  adjacency: np.ndarray            # shape: [num_nodes, num_nodes]
  node_trees: list[DecisionTreeNode]
  active_mask: np.ndarray          # shape: [num_nodes]
  lineage: dict[int, list[int]]    # parent -> children
  metadata: dict
  layer_states: dict              # Per-layer h/z, vector channels, and time cursors
  version_bundle: dict            # Weights, graph, state layout, calibration, executable bundle
  entity_ids: list                # Stable entity IDs, distinct from representation-child IDs
```

Key invariants:

- `x.shape[0] == adjacency.shape[0] == adjacency.shape[1]`；
- `len(node_trees) == x.shape[0]`；
- For undirected graphs, `adjacency == adjacency.T`;
- Rows and columns for isolated nodes may be zero, while node records are retained;
- `active_mask` agrees with isolation/pruning status.

### 3.2 `DecisionTreeNode` <a href="#section-005" id="section-005"></a>

Responsibility: represent a splittable tree within a GNN node.

Suggested fields:

```text
DecisionTreeNode
  is_leaf: bool
  depth: int
  max_depth: int
  split_feature_idx: int
  split_threshold: float
  left_child: DecisionTreeNode | None
  right_child: DecisionTreeNode | None
  local_bias: np.ndarray
  status: str
```

Methods:

```text
route(feature) -> routed_feature, leaf_id
can_split() -> bool
split(feature_dim, rng) -> bool
prune(reason) -> None
```

Splitting logic:

1. If the node is not a leaf, prevent repeated splitting;
2. If its depth has reached `max_depth`, prevent splitting;
3. Create left and right child nodes;
4. Both children inherit the parent's local bias with small perturbations;
5. Change the parent's status to non-leaf.

### 3.3 `ErrorReport` <a href="#section-006" id="section-006"></a>

Responsibility: encapsulate posterior error results.

Suggested fields:

```text
ErrorReport
  residuals: np.ndarray
  candidate_nodes: np.ndarray        # Suggestions, not approved topology changes
  threshold: float
  reasons: dict[int, str]
  metrics: dict
  prediction_id: str
  observed_at: float | None
  evidence_status: str            # MATCHED / MISSING / INVALID
  attribution: dict              # Observational, numerical, model, and resource causes
```

### 3.4 `RefineResult` <a href="#section-007" id="section-007"></a>

Responsibility: encapsulate topology reconstruction results.

Suggested fields:

```text
RefineResult
  state: GraphState
  replaced_nodes: list[int]
  new_nodes: list[int]
  isolated_nodes: list[int]
  events: list[dict]
```

## 4. Detailed core module design <a href="#section-008" id="section-008"></a>

### 4.1 GNN Layer <a href="#section-009" id="section-009"></a>

#### Function <a href="#section-010" id="section-010"></a>

Perform simplified graph message passing.

#### Inputs <a href="#section-011" id="section-011"></a>

- `x`: node feature matrix;
- `adjacency`: adjacency matrix.

#### Output <a href="#section-012" id="section-012"></a>

- `out`: aggregated node features.

#### Initial algorithm <a href="#section-013" id="section-013"></a>

```text
D_inv = diag(1 / (sum(A, axis=1) + eps))
A_hat = D_inv @ A
out = A_hat @ X
```

#### Implementation notes <a href="#section-014" id="section-014"></a>

- Isolated nodes have degree 0, requiring an added `eps`;
- A weighted message function can replace this later;
- When migrating to PyG, aggregate through `edge_index`.

### 4.2 SSM Layer <a href="#section-015" id="section-015"></a>

#### Function <a href="#section-016" id="section-016"></a>

Perform explicit state recurrence according to actual event time; independent IM01–IM06 components handle implicit solving.

#### Initial design <a href="#section-017" id="section-017"></a>

The NumPy phase can start with a lightweight linear state update:

```text
h_next = A_bar @ h + B_bar @ x
```

Temporal state can be disabled for static tasks. A linear feature transformation alone should be labeled an ordinary linear layer and cannot validate temporal memory.

#### Stable parameterization <a href="#section-018" id="section-018"></a>

- Use a validated Hurwitz parameterization for the continuous-time generator matrix, with strictly negative real parts of eigenvalues. Check stability conditions for discrete `A_bar` separately; do not conflate them;
- Apply appropriate norm constraints to candidate versions. A spectral radius below 1 at each step does not establish stability under arbitrary switching;
- Retain logs of the spectral radius of `A_bar`.

### 4.3 Tree Routing Layer <a href="#section-019" id="section-019"></a>

#### Function <a href="#section-020" id="section-020"></a>

Apply dynamic-tree routing to each node's features.

#### Initial algorithm <a href="#section-021" id="section-021"></a>

```text
for i in range(num_nodes):
    out[i], leaf_id = node_trees[i].route(x[i])
```

#### Differentiable extensions <a href="#section-022" id="section-022"></a>

- Replace hard thresholds with sigmoid gates;
- Use temperature to control the degree of soft versus hard routing;
- Use Gumbel-Softmax or a straight-through estimator.

### 4.4 Posterior Error Estimator <a href="#section-023" id="section-023"></a>

#### Function <a href="#section-024" id="section-024"></a>

Compute paired prediction errors and report candidate nodes and attribution, without directly committing a split.

#### Initial NumPy version <a href="#section-025" id="section-025"></a>

```text
if matched_observation is None:
    return ErrorReport(status="UNKNOWN", candidate_nodes=[])
residuals = scaled_norm(prediction_record.value - matched_observation.value)
candidate_nodes = diagnose_persistent_error(residuals, noise, missing_data, budget)
```

#### PDE extensions <a href="#section-026" id="section-026"></a>

- Approximate PDE residuals with finite differences;
- Use boundary-condition errors;
- Use changes in local gradients or divergence.

#### Safe LLM extensions <a href="#section-027" id="section-027"></a>

- Use violations of factual-graph paths;
- Use KL divergence;
- Use declines in retrieval confidence;
- Use scores from a logical-consistency checker.

### 4.5 Topology Refiner <a href="#section-028" id="section-028"></a>

#### Function <a href="#section-029" id="section-029"></a>

Build a new graph in an isolated copy according to candidate actions, publishing it only after migration and validation.

#### Inputs <a href="#section-030" id="section-030"></a>

- Current `GraphState`;
- `ErrorReport`；
- Splitting-policy configuration.

#### Outputs <a href="#section-031" id="section-031"></a>

- Updated `GraphState`;
- `RefineResult`。

#### Detailed process <a href="#section-032" id="section-032"></a>

1. Freeze a snapshot of the active version and first confirm the tree mode, candidate budget, and error attribution.
2. Create child nodes or experts in the candidate copy; distinguish entity IDs from representation-node IDs.
3. Reconstruct candidate edges, weights, masks, and lineage, and define restriction/prolongation operators according to task constraints.
4. Migrate every layer's h/z, vectors, edge states, and time cursors. Map optimizer statistics for new parameters; if reliable migration is impossible, reset explicitly and include the reset in validation.
5. Generate a matching layout/executable bundle. Check output consistency before and after migration, subsequent predictive benefit, regression on old tasks, and peak resource use.
6. After successful validation, publish the complete version bundle between windows. On failure, retain the original active version; reclaim the old bundle only after its tasks finish.

#### Adjacency-matrix update rules <a href="#section-033" id="section-033"></a>

The following is only a toy refinement rule for an undirected representation graph. It does not apply to entity graphs, conservative meshes, or directed causal graphs. Actual tasks must define weight/volume restriction and prolongation, conservation, and output consistency. All operations affect only the candidate copy. Let the old node be `i`, the new nodes be `l` and `r`, and the old neighborhood be $$N(i)$$:

- `A[l, r] = A[r, l] = 1`；
- For every `n in N(i)`:
  - `A[l, n] = A[n, l] = 1`；
  - `A[r, n] = A[n, r] = 1`；
- `A[i, :] = 0`；
- `A[:, i] = 0`。

### 4.6 Stability Projector <a href="#section-034" id="section-034"></a>

#### Function <a href="#section-035" id="section-035"></a>

Limit exploding features or weights.

#### SVD clipping <a href="#section-036" id="section-036"></a>

```text
u, s, vh = svd(X, full_matrices=False)
s = clip(s, 0, max_singular_value)
X_projected = (u * s) @ vh
```

#### Other policies <a href="#section-037" id="section-037"></a>

- `NormClipProjector`: clip node feature norms row by row;
- `SpectralRadiusProjector`: clip the spectral radius of the state-transition matrix;
- `LyapunovProjector`: check descent or dissipativity inequalities for a candidate V under the specified domain, inputs, and step size; reduce the step or reject on failure. Actual energy may increase under external forcing;
- `NoOpProjector`: support ablation experiments.

## 5. Key process design <a href="#section-038" id="section-038"></a>

### 5.1 Event handling and background evolution <a href="#section-039" id="section-039"></a>

```text
function on_event(active_bundle, event):
    frozen = acquire_version(active_bundle)
    report = match_prior_prediction(event, immutable_prediction_log)
    state = update_observed_state_once(frozen, event)  # Advance actual time only once
    prediction = graph_ssm_tree_predict(frozen, state)
    append_prediction(prediction, event.available_inputs, frozen.versions)
    enqueue_candidate_if_justified(report, state, budget)
    return prediction, state, report

function adapt_at_window(snapshot, paired_history):
    candidate = propose_structure_or_parameter_update(snapshot, paired_history)
    migrate_all_states_and_optimizer(candidate)
    train_or_refine_with_bounded_budget(candidate)  # Fixed graph within each forward/backward pass
    if validate_gain_regression_numerics_and_layout(candidate):
        publish_at_window_boundary(candidate)
    else:
        discard_candidate()
```

### 5.2 Separate offline training from online observations <a href="#section-040" id="section-040"></a>

Offline supervised training uses labels to compute the loss after making predictions; target labels must not enter the corresponding prediction inputs or budget selection. Online deployment uses only observations that have arrived; late results remain paired with the original prediction version. Background candidates must not overwrite the active model during its forward pass. Implicit layers solve and backpropagate with a fixed graph and parameters, returning failure status together with gradient validity; see document 45.

```text
for batch in offline_training_data:
    prediction = model(batch.available_inputs)
    loss = objective(prediction, batch.labels)
    backward_and_update_in_fixed_graph(loss)
    schedule_structure_candidate_between_steps()

for event in deployment_stream:
    prediction, state, report = on_event(active_bundle, event)
    log_prediction_and_report(prediction, report)
    run_bounded_background_adaptation_if_window_ready()
```

These are interface designs, not runnable implementations. Check candidate publication and authorization to execute real actions separately.

## 6. Exception handling <a href="#section-041" id="section-041"></a>

| Exception | Handling |
|---|---|
| Inconsistent adjacency-matrix dimensions | Raise `GraphShapeError` |
| Split exceeds maximum depth | Skip and record the event |
| Node count exceeds budget | Prohibit further splitting and enter the pruning policy |
| SVD fails to converge | Report failure of that check; norm clipping is only a numerical fallback and does not inherit the original stability conclusion |
| NaN/Inf residuals | Trigger isolation and roll back to the previous state |

## 7. Test design <a href="#section-042" id="section-042"></a>

### 7.1 Unit tests <a href="#section-043" id="section-043"></a>

#### Dynamic tree <a href="#section-044" id="section-044"></a>

- Leaf routing returns `feature + local_bias`;
- Splitting is allowed before reaching maximum depth;
- Splitting is prohibited at maximum depth;
- Left and right children exist after splitting.

#### Topology reconstruction <a href="#section-045" id="section-045"></a>

- Node count increases by 2 after splitting;
- Feature-matrix row count matches adjacency-matrix dimensions;
- Rows and columns of the old node are zeroed;
- New nodes inherit old neighbors;
- An edge connects the new nodes.

#### Stability projection <a href="#section-046" id="section-046"></a>

- Singular values do not exceed the threshold after projection;
- Projection preserves matrix shape;
- NaN inputs are detected.

### 7.2 Integration tests <a href="#section-047" id="section-047"></a>

- Construct a 5-node ring graph;
- Artificially introduce a residual at the second node;
- Perform one refinement step;
- Verify that node count increases from 5 to 7;
- Verify isolation of the old node;
- Verify that the residual event is recorded.

### 7.3 Ablation tests <a href="#section-048" id="section-048"></a>

- Disable stability projection;
- Disable isolation of old nodes;
- Disable dynamic trees, retaining only the GNN;
- Compare splitting thresholds;
- Compare maximum tree depths.

## 8. Performance design <a href="#section-049" id="section-049"></a>

### 8.1 NumPy phase <a href="#section-050" id="section-050"></a>

Suitable for experiments with fewer than a few thousand nodes. The adjacency matrix is $$N\times N$$, with space complexity $$O(N^2)$$.

### 8.2 PyG phase <a href="#section-051" id="section-051"></a>

With sparse `edge_index`, space complexity is approximately $$O(|E|)$$. This supports larger graphs and batching.

### 8.3 Dynamic-growth control <a href="#section-052" id="section-052"></a>

Required configuration:

- Maximum node count;
- Maximum tree depth;
- Maximum nodes split per step;
- Minimum interval between splits;
- Pruning policy.

## 16. Dual-loop control and cognition interfaces <a href="#section-066" id="section-066"></a>

Based on the original discussion materials, which are not included in this package, this section adds detailed designs for feedforward prediction, posterior feedback, provenance monitoring, and knowledge classification.

### 16.1 `FeedforwardPredictor` <a href="#section-067" id="section-067"></a>

Responsibility: predict high-risk regions several steps ahead to plan dynamic-tree pre-splitting, sparse GNN routing, and hardware prewarming.

```text
FeedforwardPredictor
```

Output fields:

```text
ControlPlan
  nodes_to_prewarm: list[int]
  routes_to_cache: list[tuple[int, int]]
  trees_to_presplit: list[int]
  stability_level: conservative | normal | aggressive
  confidence: float
```

### 16.2 `PosteriorCorrector` <a href="#section-068" id="section-068"></a>

Responsibility: use posterior errors as a mandatory fallback control signal to correct feedforward plans or backbone outputs.

```text
PosteriorCorrector

```

Optional actions:

- `keep`；
- `split`；
- `prune`；
- `isolate`；
- `rollback`；
- `increase_projection_strength`。

### 16.3 `ControlArbiter` <a href="#section-069" id="section-069"></a>

Responsibility: determine the priority between feedforward predictions and posterior feedback.

```text
ControlArbiter
  decide(pred_plan: ControlPlan, post_report: ErrorReport, source_report: SourceReport) -> ControlAction
```

Recommended rules:

```text
if post_report.has_critical_violation:
    feedback control takes over
elif source_report.has_untrusted_source:
    quarantine or shadow-route
elif pred_plan.confidence > threshold and post_report.residual_low:
    use predictive prewarm plan
else:
    conservative refinement
```

### 16.4 `SourceMonitor` <a href="#section-070" id="section-070"></a>

```text
SourceTag

  confidence: float
  verification_status: verified | unverified | contradicted | promoted | quarantined
  provenance: list[EvidenceRef]
  timestamp: datetime
```

### 16.5 `KnowledgeOntologyManager` <a href="#section-071" id="section-071"></a>

Responsibility: manage experience, lessons, and knowledge awaiting verification.

```text
KnowledgeOntologyManager
  classify(evidence: EvidenceRecord) -> KnowledgeStatus
  promote(shadow_item) -> StableExperience
  demote(shadow_item) -> NegativeLesson
  quarantine(item, reason) -> None
```

Knowledge states:

- `local_positive_experience`: correct within a specified range of conditions;
- `local_negative_lesson`: incorrect or high-risk within a specified range of conditions;
- `unverified_shadow`: known but not yet verified;
- `contradicted`: falsified by real evidence or highly trusted simulation;
- `promoted`: promoted after multiple rounds of validation.

### 17.4 `CrossDomainErrorEstimator` <a href="#section-076" id="section-076"></a>

## 20. JEPA / JSBO world-model bridge interfaces <a href="#section-087" id="section-087"></a>

Based on the original discussion materials, which are not included in this package, this section adds the core interfaces of `sgd_net.jepa_bridge`. The module connects latent representations from I-JEPA, V-JEPA, or other self-supervised world models and converts them into structure-preserving SGD-Net states.

### 20.2 `JEPAAdapter` <a href="#section-089" id="section-089"></a>

The adapter should not assume that every JEPA is an image model; implementations should allow video, trajectory, sensor, graph, and multimodal latent representations.

### 20.3 `JSBOBridgeOperator` <a href="#section-090" id="section-090"></a>

Responsibility: estimate the metric of the target structural space and pull it back to JEPA latent space.

```text
MetricPullbackProjector
  estimate_metric(bridge_state: BridgeState) -> MetricTensor
  compute_jacobian(latent: JEPALatentTensor) -> Jacobian
  pullback(jacobian: Jacobian, metric: MetricTensor) -> LatentMetric
```

Core constraint:

```text
G_latent = J_bridge.T @ M_struct @ J_bridge
```

### 20.5 `KoopmanProjector` <a href="#section-092" id="section-092"></a>

## 21. Application-first execution, backend abstraction, and simulator shadow interfaces <a href="#section-097" id="section-097"></a>

Based on the application-first and simulator-loop materials (`SGD-Net应用先行与模拟器闭环/`), this section adds core runtime, backend, trace, and simulator-shadow interfaces. The goal is to run the same SGD-Net application first on third-party CPU/GPU/NPU/TPU backends, then replay the same trace with an SGD-TPU simulator/CModel to identify hardware opportunities and bottlenecks.

### 21.1 Unified `Backend` interface <a href="#section-098" id="section-098"></a>

Responsibility: abstract CPU, vendor-accelerator, SGD-TPU-simulator, and hybrid backends.

```text
Backend
  name: str
  capabilities() -> BackendCapabilities
  compile(op_graph) -> BackendExecutable
  run(executable, inputs, trace_policy) -> BackendRunResult
  profile() -> BackendProfile
  replay(trace: WorkloadTrace) -> ReplayResult
  fallback(reason: str) -> Backend
```

### 21.2 `BackendCapabilities` <a href="#section-099" id="section-099"></a>

Responsibility: describe a backend's supported operators, dtypes, layouts, dynamic shapes, and profiling capabilities.

```text
BackendCapabilities
  supported_ops: list[str]
  supported_dtypes: list[str]
  preferred_layouts: list[str]
  dynamic_shape_support: bool
  sparse_support_level: none | basic | advanced
  control_flow_support_level: none | host | device
  profiling_support_level: none | coarse | detailed
```

### 21.3 `PlacementPlan` <a href="#section-100" id="section-100"></a>

Responsibility: record why the runtime places an operator on a particular backend.

```text
PlacementPlan
  op_id: str
  primary_backend: str
  shadow_backend: str | None
  fallback_backend: str
  trace_policy: dict
  diff_policy: dict
  safety_policy: dict
  reason: str
```

### 21.4 `WorkloadTrace` <a href="#section-101" id="section-101"></a>

Responsibility: convert actual application execution into a trace that supports replay, difference analysis, and modeling.

```text
WorkloadTrace
  trace_id: str
  app_name: str
  run_config: dict
  input_summary: dict
  quality_metrics: dict
  ops: list[OpTrace]
  backend_events: list[BackendEvent]
  memory_events: list[MemoryEvent]
  control_events: list[ControlEvent]
  artifacts: dict
```

### 21.5 `ShadowExecutor` <a href="#section-102" id="section-102"></a>

Responsibility: execute primarily on the vendor backend while the SGD-TPU simulator backend executes the same trace on a shadow path.

```text
ShadowExecutor
  run_primary(plan: PlacementPlan, inputs) -> BackendRunResult
  capture_trace(primary_result) -> WorkloadTrace
  run_shadow(trace: WorkloadTrace) -> ReplayResult
  compare(primary_result, shadow_result) -> DiffReport
```

### 21.6 `BottleneckAnalyzer` <a href="#section-103" id="section-103"></a>

Responsibility: compare the vendor baseline with the simulator backend and produce application, runtime, or hardware recommendations.

```text
BottleneckAnalyzer
  analyze(vendor_report, sim_report, trace) -> BottleneckReport
  generate_roofline(report) -> RooflineArtifacts
  suggest_pgo(report) -> list[PgoSuggestion]
  suggest_hardware(report) -> HardwareSpecSuggestion
```

### 21.7 Safety constraints <a href="#section-104" id="section-104"></a>

Simulators and uncalibrated backends must not directly control real devices. Safety rules:

```text
if backend == simulator and calibration_level < required:
    allow_shadow_only = true
if output_diff > threshold:
    quarantine_result()
if op.is_safety_critical:
    require_cpu_or_ppu_reference_check()
```
