## 1. The First Research Round Answers Only Three Questions <a href="#section-001" id="section-001"></a>

First, after inference-graph refinement, is learned state migration more accurate and computationally cheaper than copying, zeroing, or recomputation? Second, can a budgeter distinguishing insufficient computation from insufficient observations improve task outcomes at equal end-to-end cost? Third, can embodiment graphs and task-effect representations reduce data needed when changing hand types? These correspond to H1, H2, and H3 in the architecture proposal.

Each question requires separate support. Model success cannot automatically be attributed to graph refinement, and safety checks rejecting many actions do not prove improved policy quality. Report raw candidate quality, execution outcomes after checks, rejection rates, completion time, and computational costs together.

## 2. Baselines and Fair Comparisons <a href="#section-002" id="section-002"></a>

| Comparison level | Required baselines or related work | Controlled variables and boundaries |
|---|---|---|
| Increment over the original project | Faithfully simplified original SGD-Net: fixed graph, SSM, original error feedback; add new mechanisms individually | The original design has no unified training implementation; record implementation choices rather than calling a self-built weak baseline measured original-model performance |
| Graph and temporal combination | FACTS; equal-width GNN+GRU, GNN+SSM, GNN+Attention | Identical inputs, training data, and search budgets; report parameter-matched and latency-matched comparisons separately rather than substituting one for the other [^R03] |
| Cross-embodiment world models | Scaling Cross-Embodiment World Models for Dexterous Manipulation; GraphOp-WM | The former is the closest related work; the latter's public abstract mainly concerns morphology-parameter changes, so distinguish limb-parameter changes from entirely new hand topology. If reproduction is impossible, compare mechanisms only [^R06][^R07] |
| Action learning | MaIL and reproducible point-cloud diffusion policy baselines | Identical visual encoders, historical windows, action spaces, and data splits; disclose visual-pretraining data differences separately [^R02] |
| Contact and hand adaptation | CGP, T-Rex, DPP, GraspGraphNet | Represent compliance control, multirate tactile fusion, human-demonstration transfer, and graph-conditioned grasping, respectively; differing tasks and sensors preclude mixed success-rate rankings [^R08][^R09][^R10][^R12] |

“Baselines” here have three categories: directly runnable, reimplemented from papers, and mechanism-only comparisons. Register papers, code, weights, data, and licenses individually; code availability does not imply complete reproducibility. Without unified tasks and evaluation protocols, do not claim to beat “Top X.”

## 3. Data Splits: Truly Isolating Cross-Hand Generalization <a href="#section-003" id="section-003"></a>

Initially use three training hand types and one completely held-out test hand, rotating holdouts when simulation conditions permit. The test hand's geometric description and joint constraints may be inputs, but its action trajectories, contact labels, and calibrated task performance cannot be used for zero-shot training or model selection. Explicitly count URDF-parameter inputs among allowed priors.

Separate at least four generalization types: new objects for the same hand, new dimensions with unchanged topology, topology changes such as removed fingers or added joints, and entirely new hand types. Object instances, task combinations, and contact materials also require separate independent holdouts. Randomly splitting continuous trajectories leaks temporal and object information and cannot establish transfer.

The initial few-shot proposal uses 10, 50, and 100 demonstrations, reporting total duration, success/failure fractions, collection methods, and tuning counts rather than counts alone. Report zero-shot, calibration-only, decoder-adapted, and full-model-adapted results separately; adjustments to IK, contact biases, and control gains must also be registered. DPP's “no robot demonstrations” does not mean no human data, mappings, or control design. [^R12]

Vision, touch, joint, and current data retain their own timestamps, units, missingness masks, and sensor versions. Synchronization error should itself be a stress-test variable; interpolated high-frequency sequences are not actual high-frequency observations. Training targets use only historical inputs available at the time; future observations serve only offline supervision and evaluation.

## 4. Ablations and Evaluation Metrics <a href="#section-004" id="section-004"></a>

| Hypothesis | Minimum ablations | Main measurements |
|---|---|---|
| H1 State migration | Zeroing, parent-node copying, re-encoding, reconstruction loss only, added dynamics consistency, added action-readout consistency | Action jumps before/after refinement at the same physical instant; cross-resolution prediction errors; added computation; long-term drift |
| H2 Budget allocation | Fixed steps; single residual threshold; compute allocation only; added observation option; complete typed budgeter | Success under equal time/energy budgets; deadline violations; ineffective refinements; observation costs; checking and fallback shares |
| H3 Cross-hand semantics | Hand ID; geometry vectors; embodiment graph; native actions only; task effects plus native actions | Held-out-hand zero-shot success; few-shot learning curves; unreachable-action rates; contact failures and object-damage proxies |
| Contact prediction | Touch only as input; separate tactile prediction; joint contact/action-effect supervision | Contact-event precision/recall, slip-warning lead time, calibration error, downstream completion |
| Runtime guarantees | Same model with checks enabled/disabled, compared in simulation first | Hazardous-candidate detection, false rejection, UNKNOWN fraction, intervention rate; do not hide policy failures using only survivors after checks |

Report prediction errors separately for position, orientation, velocity, force, and contact state, retaining units. A normalized weighted sum is not a single physically meaningful error bound. Use appropriate rotational distances for orientation; accuracy alone is insufficient with imbalanced contact states.

Use at least three independent training seeds initially, with confidence intervals grouped by complete episodes or objects/hand types; frames are not independent samples. Freeze primary metrics, stopping rules, and hyperparameter budgets before examining tests. No observed accidents in small samples do not prove safety, and simulation contact errors must not be ignored by default.

## 5. Phased Implementation and Exit Criteria <a href="#section-005" id="section-005"></a>

**Phase A: Controlled examples.** Use low-dimensional mass–spring or rigid-body examples with contact and checkable reference states. Validate state migration, unit consistency, readout consistency at fixed physical times, budget termination, and fallback. Expose switching-stability counterexamples, missing measurements, and stale observations here. Passing examples shows implementation conforms to expectations, not real robot validation.

**Phase B: Fixed-graph offline models.** Train a shared temporal backbone, action decoder, and world model before adding refinement and budgeters. First establish that the world model is more useful than holding the previous state or simple motion models, and check multistep rollout bias. Prevent policies from exploiting world-model flaws for spurious rewards; real or independent simulation evaluation must be separate from the training world model.

**Phase C: Unified simulation cross-hand experiments.** Test H1–H3 under Section 3's holdout protocol. If copied states and learned migration do not differ significantly, retain the simple implementation; if fixed budgets are better, remove the learned budgeter; if new-hand gains come only from specific calibration, narrow transfer conclusions.

**Phase D: Controlled hardware validation.** Once sensing, execution, checkers, and stopping mechanisms are ready, begin with low speeds and few tasks, recording all interventions and failures. This is a later research gate; the current document does not imply readiness for hardware validation.

**Phase E: Software/hardware mapping.** Extract real traces only after operator graphs stabilize; establish GPU/CPU references before Aegis-X CModel, RTL, or board-level evaluation. CModel estimates, cycle models, RTL simulations, and board measurements are different evidence levels.

Development duration depends on data, simulation, and staffing, so no fixed week count is promised. Success requires reproducible, practically meaningful benefit for at least one hypothesis at acceptable added cost; assess statistical significance and engineering value together.

## 6. First Runnable Dimensions and Storage Accounting <a href="#section-006" id="section-006"></a>

Start with batch=1, at most 128 nodes and 1024 edges, hidden width 128, 4 temporal blocks, prediction horizon 8, at most 2 candidate rollouts, and 2 graph refinements. These are adjustable experimental limits. Configure native action dimensions from the arm and hand's actual degrees of freedom; if using capacity 32, insufficient capacity requires recompilation or explicit rejection rather than truncation. Edge/node overflow likewise needs visible degradation semantics.

BF16 buffer estimates:

| Object | Formula | Size |
|---|---|---:|
| Single-layer node hidden states | 128 × 128 × 2 bytes | 32 KiB |
| Four-layer single-trajectory states | 4 × 32 KiB | 128 KiB |
| Observed trajectory plus two independent candidate states | 3 × 128 KiB | 384 KiB |
| One copy of node features | 128 × 128 × 2 bytes | 32 KiB |
| One copy of edge features, edge width 64 | 1024 × 64 × 2 bytes | 128 KiB |

These exclude encoder activations, weights, optimizers, gradients, double buffering, indices, timestamps, and refinement mappings. Retaining intermediate states for every prediction step further scales relevant portions with horizon; streaming rollouts and recomputation reduce peaks but alter computation costs. This is a node-vector-state configuration; SSMs with additional state axes require recalculation rather than copying the table.

The original Aegis-X R1 document's 12 MiB SPM and 512 KiB SAFE are design specifications; residency of the above states still depends on other occupancy and concurrent scheduling. Ten million BF16 parameters alone occupy about 20 MB, exceeding 12 MiB and requiring layered loading or validated quantization. SAFE space is not a general model buffer pool. Theoretical TOPS cannot determine end-to-end control frequency.

## 7. Boundaries of Mapping to Aegis-X <a href="#section-007" id="section-007"></a>

| Model work | Candidate execution resources | Measurements or constraints required |
|---|---|---|
| Encoding, linear projections, action/prediction heads | Matrix and SRAM/DMA | Small-matrix utilization, weight transfers, activation peaks |
| Temporal updates, gating, reductions | Vector/Scan | Specific SSM state layouts and gating dependencies; do not assume all updates permit parallel scans |
| Graph messaging and aggregation | Sparse/Vector, bucketing, bounded indices | Scatter conflicts, degree distributions, index bandwidth, sorting, and graph-building time |
| Graph refinement, P/Q state transfers | Coordinated Vector and DMA | State versions, validity masks, worst-case copied volume, buffer lifetimes |
| Action-candidate checks and submission | Existing contracts and independent checking paths | Reserve checking, submission, and fallback time; model budgets cannot exhaust control cycles |

With fixed widths and bounded edge counts, local graph propagation has controllable scale; linear layers may still cost node count times hidden width squared, and naive neighbor searches may be quadratic in node count. Limiting neighbor counts does not automatically bound search costs. Dynamic graph construction and transfers belong in total latency; timing only network forward passes is insufficient.

BF16 may be the initial neural-network precision; numerical experiments should determine whether geometric transforms, critical reductions, error bounds, and checkers require FP32. Low-bit quantization requires reevaluating prediction intervals and action behavior. Existing TSPUs for specific decoding scenarios cannot directly be claimed to support graph inference, flow matching, or all temporal operators.

For each task, retain end-to-end P50/P95/P99 latency, worst observation age, peak memory, DRAM bytes, peak node/edge counts, candidate counts, refinement counts, and execution status. Candidate world-model states must remain separate from committed observation states; the original data-plane provisional/committed concept may inform this, but their physical semantics need independent definitions.

Dedicated new silicon modules are not recommended now. First complete compiler/runtime support for bounded graphs, masks, state versions, candidate isolation, and budget accounting; discuss hardening only when real traces reveal persistent bottlenecks.

## 8. A Second Validation Track for Transfer to Scientific Research <a href="#section-008" id="section-008"></a>

Particle systems or PDE mesh refinement may test H1: preserve physical fields, conserved quantities, and boundary conditions across refinement and compare error–cost curves. Graph simulators are clear precedents, so “graph networks simulate physics” is not a new contribution. [^R04] State-migration principles may be shared with dexterous hands, but use different data, losses, and evaluation protocols without promising shared weights.

For project-related neurobehavioral and signaling–synapse researchers, current proposals provide methodological support: separately record observation residuals and model errors; preserve traceable state migration in multiscale models; compare added observations with refined computation at fixed compute. Specific scientific objects, available data, and existing experimental platforms must be matched to researchers' actual projects before determination; the model proposal does not establish improved scientific results.

Molecular tasks require chirality handling and cannot unconditionally use reflection-invariant representations; predictive associations in biological or neural time series are not directly causal mechanisms. Dissipative, collision, and friction systems also cannot claim correct physics solely from a “symplectic structure” label. Retain these boundaries when reusing JSBO.
