## 1. Task Definition and Minimal Model <a href="#section-001" id="section-001"></a>

The first model targets interaction sequences of trackable objects. Given historical observations, environmental conditions, and specified actions, it predicts future object states, contact events, and observation distributions. The model answers “what might happen after taking an action”; it does not directly decide to execute that action. Start with short-horizon mechanical/particle environments, rather than including all video understanding, long-text planning, and open-world tasks in one training run.

The dynamics component is shared with TC, but WM requires neither embodiment-specific action decoding nor device control; it can also support simulation surrogates, field prediction, and related tasks. With only action-free video, the result is an observation prediction model; learning action effects cannot be claimed without corresponding data.

Initial input specification: a history of 16 observation events, N≤128, E≤1024, d=s=128, 4 blocks, and prediction H=8. Event intervals use real Δt; 8 steps cannot uniformly be interpreted as a fixed number of seconds. Example physical states include position, velocity, object properties, and contact mode; position estimates and confidence are kept separate under occlusion.

## 2. Component Configuration and Specialized Units <a href="#section-002" id="section-002"></a>

Standard data/training/runtime units follow 36; the model selects B01/B03/B04/B06/B07/B08, C01–C05/C07/C08, D01–D07, E01/E02/E03/E08, and F01/F02/F08. F03–F07 and G04 are reserved for later ablations; D08 and E04/E06/E07 are disabled in the initial version, and C06 is enabled only for periodic environments.

| Domain unit | Corresponding basic units | Input → output and composition |
|---|---|---|
| WM01 Object slots and association | A03, B01, B07 | Local image features → entity slots, visibility, matching probabilities; environment entity labels may be used directly in the first round |
| WM02 State belief encoding | B08, D04/D05 | Historical measurements → hidden memory and current state estimates; retain masks for missing measurements |
| WM03 Action conditioner | B06 | Known actions and duration → per-node interaction conditions; record transformations between world and embodiment coordinates |
| WM04 Conditional transition distribution | E01 | h, z, actions → increment means, positive scales, and mode logits |
| WM05 Observation generation/likelihood | E02 | Future states/latent representations → distributions of observable variables; pixel decoding is optional |
| WM06 Latent future prediction | G04 | Context latent representations and actions → teacher future representations; a training auxiliary that does not independently supply physical units |
| WM07 Multistep rollout | F08, E01 | State snapshot and action sequence → independent H-step imagined trajectories |
| WM08 Task/termination readout | E08 | Future states → task costs, termination or failure probabilities; corresponding labels are required |

Using ground-truth entities in WM01 isolates perception from dynamics. Replace them with real visual tracking only afterward, and separately report how perception errors affect rollouts.

## 3. Forward Pass and Output Contract <a href="#section-003" id="section-003"></a>

For each observation event, first update object identities, time, and the current graph. Each of the four spatiotemporal blocks advances its memory once, and WM02 outputs the current belief. Given an action sequence, copy the state and let WM04 predict the next state; encode that prediction as input for the next imagined step and continue rolling out. Predicted observations must not masquerade as real observation innovations, and memory for the real trajectory is not overwritten.

The following conditional probability factorization can define training:

$$
p(x_{1:H},o_{1:H}\mid h_0,u_{0:H-1})
=\prod_{k=1}^{H}p_\theta(x_k\mid h_{k-1},u_{k-1})p_\psi(o_k\mid x_k,h_{k-1}).
$$

Supervise the state head when x is known; when x is unknown, choose an explicit latent-variable training method or train only the observation head, without assuming that latent states have real coordinates. For continuous variables, use diagonal Gaussians in the first round, with scales obtained from softplus outputs plus a positive floor; use appropriate local parameters/manifold errors for rotations and categorical distributions for contact modes. Compare mixture distributions or sampling models when multimodal action outcomes appear.

Outputs include predicted means/scales, contact probabilities, validity, physical time at each step, graph/model versions, and observation ages. List latent-space distances separately rather than mixing them with errors in millimeters, newtons, or other physical units.

## 4. Data and Training Steps <a href="#section-004" id="section-004"></a>

Store episodes, entities, actions, Δt, observations, state availability, environmental parameters, and termination reasons. Hold out complete environmental parameters, object combinations, and interaction sequences; adjacent frames within an episode must not cross training and test splits. Start with simulation data providing ground-truth states and actions, then add perception noise and real data.

1. Fix perception or use ground-truth entities; fix the graph and budget, and train one-step transitions and observation readouts.
2. Train short sequences in real temporal order; reset states at the episode start in each batch and explicitly record the truncated backpropagation strategy for consecutive segments.
3. Add multistep rollout losses, measure teacher forcing and free rollout separately, and record error growth with horizon.
4. Add WM06 when visual pretraining is needed; teacher future views enter only the target branch and must not leak into current inputs.
5. Add graph refinement and the budgeter, using paired coarse/fine data and offline benefit labels to control actual total cost.

The loss comprises negative log-likelihoods for valid states/observations, contact cross-entropy, applicable physics residuals, and optional latent-space prediction and state migration terms. List each weight and training-set normalization constant. Calibrate on independent episodes and recheck on the distribution after closed-loop selection.

## 5. Baselines, Ablations, and Acceptance Criteria <a href="#section-005" id="section-005"></a>

Required baselines: holding the previous state, constant velocity, a simple state-space model, fixed-graph GNN+GRU, GNN+SSM with identical inputs, and reproducible relevant world models. FACTS already combines graph memory with selective state spaces, so that combination alone must not be treated as a new contribution. [FACTS](https://arxiv.org/abs/2410.20922)

Ablate WM02 temporal memory, action conditioning, EGNN, observation correction, multistep loss, P/Q, and the budgeter. Metrics include per-step state errors, distribution NLL/coverage, contact classification, long-term drift, differences in action responses, and end-to-end cost. For state prediction tasks, visual video quality is not the primary metric.

If the model does not outperform simple dynamics, first inspect the data and task; if it is equally accurate without action inputs, check for insufficient action variation in training or leakage. Passing the initial version means obtaining reproducible prediction improvements on a task frozen in advance; it does not justify calling the model a general-purpose world model.

## 6. Extension to Other World Models <a href="#section-006" id="section-006"></a>

Continuous fields require grid/particle encoding, boundary conditions, field readouts, and solver interfaces; object slots cannot simply be reused to directly output PDE solutions. Temporal and budget mechanisms can be retained while known domain components are delegated to the numerical core. NeuralGCM is a reference for hybrid dynamics modeling, but its domain-specific findings do not establish capabilities of this model. [NeuralGCM](https://www.nature.com/articles/s41586-024-07744-y)

Language-semantic objectives are supplied as conditions by a frozen encoder; if planning is required, connect the candidate and control layers from [38 Physical AI](38.md). A reproducible deliverable requires saved data splits, configurations, weights, calibration packages, and complete rollout replays.

## Lyapunov Configuration Supplement (2026-09-12) <a href="#section-007" id="section-007"></a>

Memory/observer or numerical errors can connect to L02–L07; first define errors under identical inputs and the allowed disturbances. Do not force all trajectories of the real system to converge. L01/L08 record applicability, assumptions, and evidence; see [44 Lyapunov Stability in Detail](44.md) for mathematics and unit interfaces. This is a design awaiting implementation, not a stability validation result.

## Mathematical Task Contract and Extension Priorities (2026-09-12) <a href="#section-008" id="section-008"></a>

Target future trajectories or conditional distributions given the history and actions; register the prediction horizon, state errors, event probability calibration, and closed-loop loss separately. Do not impose a unique future in partially observable environments; when delayed queries fail, first inspect information and memory capacity.

Use [48 Mathematical Assessment](48.md) to distinguish representational, learning, and numerical solution capabilities; follow [49 Task Cards](49.md) by starting with fixed-structure baselines and then adding individual extensions supported by evidence. There is no need to first simulate the complete computation of other models.
