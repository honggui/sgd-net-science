## 1. Minimal Task and Model Boundaries <a href="#section-001" id="section-001"></a>

Start with short-horizon grasping/contact adjustments using a fixed robotic arm and several hand types. Inputs are vision, joints, touch, goals, and embodiment descriptions; outputs are native actions and predictions of their effects. The world model provides predictions, the policy provides candidates, and the local controller executes; evaluate the three functions separately.

Maintain three distinct structures: the real embodiment graph, the dynamic contact graph, and the inference refinement graph. Refining sample points on an object's surface cannot add real fingers or change actuator degrees of freedom. A new hand type requires a geometric description as well as explicit control modes, joint limits, sensors, and time delays.

Initial dimensions remain N≤128, E≤1024, d=s=128, 4 blocks, and H=8; allow at most two candidates and two representation refinements. Configure native action dimensions according to the actual degrees of freedom of the arm and hand, using padding with action masks; reject unsupported control modes rather than truncating them.

## 2. Trainable Units and Control Units <a href="#section-002" id="section-002"></a>

Enable E03/E04 and F03–F08 on top of the WM configuration, and connect H03–H08. Add tactile/joint branches to B04 and embodiment conditions to B06. E07 may replace the direct action distribution head in multimodal policy experiments; do not use D08 in the first round.

| Domain unit | Basic units | Input → output and details |
|---|---|---|
| TC01 Embodiment encoder | C02, B03/B06 | Links, joints, limits, and control modes → embodiment nodes and conditions |
| TC02 Contact observer | B04, C03 | Touch/relative geometry → contact regions, validity, slip features |
| TC03 Task-effect head | E03 | Goal and current state → object pose changes/feasible contact effects |
| TC04 Native action decoding | E04 | Effects, embodiment, state → action chunks in the selected mode, such as joint targets/torques |
| TC05 Contact world model | E01/E03 | Actions, objects, embodiment → future states and contact distributions |
| TC06 Local tactile correction | B04, E04, H05 | New touch and uncommitted action suffix → bounded corrections |
| TC07 Candidate planner | F03/F08, E08 | Candidate actions and rollout costs → selected candidate and prediction rationale |
| TC08 Independent execution interface | H03–H06 | Checked actions → controller ACK and execution status; not a trainable layer |

Native action fields must have fixed physical meanings. Position targets, velocity targets, impedance parameters, and torques must not share a single unmarked vector. Prefer one mode supported by an existing low-level controller in the initial version.

## 3. Operation of One Control Cycle <a href="#section-003" id="section-003"></a>

When a new event arrives, synchronize identities and time, then update the real temporal memory once. TC03/TC04 generate candidates, TC05 rolls them out in independent snapshots, and TC07 ranks them by task, reachability, and predicted risk. F03 may select local graph refinement, but H03 reserves time for checks and fallback. Finally, independent checks and the controller receive the action.

An action chunk consists of a committed prefix and a modifiable suffix. TC06 cannot undo an executed prefix; modifying the suffix requires a new version and validity period. Higher-frequency touch requires actual sensors and timestamps; interpolation does not create new information.

When jointly training the policy and world model, an effect-consistency term can encourage the world model's predicted object effects to approach target effects. Independent environment validation is still needed to prevent the policy from exploiting world-model errors. Low predicted variance is not a safety certificate; checks return unknown when boundary information is insufficient.

## 4. Training Objectives and Data Preparation <a href="#section-004" id="section-004"></a>

Core losses are action imitation or action-distribution NLL, future physical-state NLL, contact classification, effect errors, and consistency of current refinement readouts. Add a common-scale dynamics loss for P/Q to avoid directly subtracting coarse and fine coordinates node by node. Unmeasured tactile locations must not be labeled as no contact.

First train on a mixture of known embodiments, completely holding out new embodiments. Separately test new objects, dimensional changes with unchanged topology, topology changes, and entirely new hand types. Specify the URDF/calibration priors allowed for zero-shot evaluation in advance; use of new-hand demonstrations, control-parameter tuning, or contact-bias adjustments places results in the corresponding adaptation category.

Construction sequence: fix perception and low-level controllers → train a fixed-graph world model → train action decoding → joint effect supervision → coarse/fine representations and state migration → an offline benefit budgeter → controlled closed-loop evaluation. First-round simulation data must cover action outcomes and failures; collecting only successful demonstrations cannot support a claim of risk recognition.

CGP can inform contact/compliance control and T-Rex asynchronous tactile fusion; their sensor and control assumptions require independent verification. [CGP](https://arxiv.org/html/2603.05687v1), [Official T-Rex repository](https://github.com/ZhuoyangLiu2005/T-Rex)

## 5. Fair Comparisons and Deliverables <a href="#section-005" id="section-005"></a>

Directly relevant baselines include cross-embodiment particle world models, which already provide a clear precedent for a shared state/action interface. [Scaling Cross-Embodiment World Models](https://arxiv.org/abs/2511.01177) The same task also requires ablations with a fixed-graph policy, embodiment-ID-only conditioning, no touch, no P/Q, and fixed inference-step counts.

Report raw candidate validity, success after checks, rejection/intervention rates, object-instability or damage proxies, transfer-data curves, task duration, and latency tails separately. Success after a checker filters many incorrect candidates cannot be attributed solely to the policy.

Validate low-dimensional examples and simulation first, then proceed to hardware under the actual platform protocol. Save every observation, candidate, graph version, action unit, committed prefix, controller response, and failure reason. Extensions to mobile robots, soft robots, or assembly require rebuilding embodiment/contact/action models, rather than merely increasing node counts.

## Lyapunov Configuration Supplement (2026-09-12) <a href="#section-006" id="section-006"></a>

Connect local closed loops to CLF/CBF, input/disturbance budgets, and contact-switching checks through L01–L08; explicitly handle relaxation, infeasibility, and sampling delays. L01/L08 record applicability, assumptions, and evidence; see [44 Lyapunov Stability in Detail](44.md) for mathematics and unit interfaces. This is a design awaiting implementation, not a stability validation result.

## Mathematical Task Contract and Extension Priorities (2026-09-12) <a href="#section-007" id="section-007"></a>

Evaluate continuous states and discrete contact modes separately; jointly report tracking errors, constraint violations, contact-event times, and actual deadlines. Do not assume smoothness near impacts. Implicit residuals must be considered together with solve conditions; a smaller one-step residual cannot replace closed-loop safety validation.

Use [48 Mathematical Assessment](48.md) to distinguish representational, learning, and numerical solution capabilities; follow [49 Task Cards](49.md) by starting with fixed-structure baselines and then adding individual extensions supported by evidence. There is no need to first simulate the complete computation of other models.
