## 1. Define the Prediction Target Before Assembling the Network <a href="#section-001" id="section-001"></a>

For the initial version, choose a protein–ligand candidate-ranking task with reliable experimental labels. Fix one measurement endpoint and experimental system; input structural candidates, sequences, and experimental conditions, and output predictions and uncertainties for that endpoint. Antibody research requires a separate protein–protein and functional-endpoint configuration; small-molecule affinity weights cannot simply be reused.

Retain three distinct model tasks: static structure/property prediction, dynamics prediction from real trajectories, and candidate generation. The first does not enable a temporal SSM; the second requires real trajectories and environmental conditions; the third has independent denoising/flow time, which must not be interpreted as dynamics time.

AlphaFold 3 and Boltz provide sources of structure and interaction models that can be connected. The initial version reads their outputs, freezes upstream components, and adds testable downstream SGD graph enhancement, rather than inserting layers into their internals before confirming code, weights, and licenses. [AlphaFold 3](https://www.nature.com/articles/s41586-024-07487-w), [Official Boltz repository](https://github.com/jwohlwend/boltz)

## 2. Component Configuration and Specialized Units <a href="#section-002" id="section-002"></a>

Enable B02/B03/B06/B07, C01/C02/C03/C05/C07/C08, D01/D02/D03/D06/D07, E05/E06/E08, and F01/F02/F08; use B08 only with direct state labels. D04/D05 are disabled in the initial version. F04's candidate mode is used for candidate ranking; C04/F05/F06/F07 are used only in graph-refinement experiments. E07 is a later generation branch.

| Unit | Corresponding basic units | Input → output and internal responsibilities |
|---|---|---|
| MOL01 Chemical entity parsing | A01/A02, B03, C02 | Atoms, bonds, formal charges, stereochemistry, chains, and residues → typed nodes/edges |
| MOL02 Sequence and pocket encoding | B02/B06/B07 | Protein sequences and candidate binding regions → conditioning features; frozen upstream version |
| MOL03 Chemical geometry block | C05/C07, D02/D07 | Bond graph and spatial neighborhoods → geometrically enhanced nodes; explicit chirality mode |
| MOL04 Conformational ensemble readout | E08 | Multiple conformational representations and conditions → ensemble features/distributions; uniform weights are not assumed to define a thermal equilibrium distribution |
| MOL05 Property/endpoint head | E05/E06 | Molecules and experimental conditions → means/scales for selected endpoints, with separate heads for different endpoints |
| MOL06 Structural validity checks | F01, H04 | Candidate coordinates → bond, clash, chirality, and constraint status |
| MOL07 Local candidate refinement | F04/F07 or E07 | Constrained regions and global context → new candidates; retain global rechecking |
| MOL08 Multifidelity ranking | F02/F03, G08, H01 | Model, physical-tool, and experimental results → recommendations for the next evaluation batch |

Within MOL05, affinity, selectivity, expression, function, exposure, and toxicity require separate endpoint definitions. Data measured under different conditions cannot be directly merged; structural confidence such as pLDDT is only a structure-related feature and cannot serve as ground truth for efficacy.

## 3. Reference Tensors and Forward Pass <a href="#section-003" id="section-003"></a>

A small debugging instance uses a single pocket and ligand graph, with N≤512, E≤8192, d=128, 4 geometry blocks, and at most 4 conformations. Explicitly crop/partition inputs exceeding these bounds and record global context, without claiming coverage of complete macromolecules; interactions outside the pocket may limit the model. When evidence does not support a precise pocket, propagate localization uncertainty into results.

The forward pass is parsing → sequence/atom encoding → bond and spatial edges → geometry blocks → node/ensemble pooling → experimental-condition heads. Extensive energy heads sum atomic contributions; whole-system endpoints may use appropriate set readouts. Output structural confidence and experimental-endpoint uncertainty separately for each conformation.

When training on real energies, a consistency path using $$E_\theta(X,Z,c)$$ and $$F_i=-\nabla_{x_i}E_\theta$$ can be used. Gradients of an arbitrary affinity regression head are not atomic forces; static geometric coordinate correction is not MD. Disable this physical head without corresponding energy/force labels, using external tools for independent evaluation.

## 4. Training Data, Losses, and Sequence <a href="#section-004" id="section-004"></a>

Each experimental record stores chemical entities, protein constructs, measurement type, units, experimental conditions, batch, detection limits, source, and time. Censored results require suitable interval/censoring likelihoods; “below detection limit” must not be treated as an exact number. Untested candidates are not negative samples.

The static initial version uses endpoint NLL/regression loss plus a ranking term where supervision is available. Structural constraints are optional and must specify which coordinates their gradients modify; local refinement also requires evaluation of global structures and distributions. The dynamics version adds real-trajectory losses; the generation version uses a selected diffusion/flow objective. Naming several losses does not imply that training data exist.

Steps:

1. Clean labels, units, duplicates, and batches; establish fingerprint/descriptor-plus-simple-regression baselines and original upstream-model rankings.
2. Freeze sequence and structure sources and train only MOL03–MOL05; compare benefits under identical data budgets.
3. Hold out a calibration set and examine out-of-domain degradation on new chemical scaffolds/new protein families.
4. Introduce local refinement when failed structures and reliable references are available; compare against global resampling at equal candidate counts/compute.
5. Then add multifidelity screening; evaluate final candidates with independent high-fidelity calculations or experiments to avoid optimizing only the model's own score.

Data splits jointly consider ligand scaffolds, protein sequence/family similarity, and time; record duplicate structures, homologous complexes, and overlap with upstream pretraining data. With scarce labels, first compare frozen features plus simple heads rather than assuming joint fine-tuning is better.

## 5. Acceptance Criteria and Cross-Domain Connections <a href="#section-005" id="section-005"></a>

Define metrics by endpoint, including MAE/correlation, ranking enrichment, calibration, valid-candidate fraction, out-of-domain performance, and actual total cost. Group statistics by target/scaffold or batch; high predicted affinity cannot replace functional validation.

Required ablations: no SGD enhancement, ordinary GNN versus geometry blocks, no sequence conditioning, single conformation versus ensemble, no local refinement, and fixed-fidelity policies. Retain simple modules if simple reranking achieves equivalent effects.

When extending into signaling and synapse research, use candidate structural features as optional inputs to [43 Signaling–Synapse Model](43.md); functional prediction requires data from that system itself. The model cannot skip the evidence levels between structure, binding, activation, and disease phenotypes.

Deliverables should include task definitions, data/license inventories, fixed upstream versions, domain graph schemas, training and calibration configurations, weights, and independent candidate evaluation reports. This document has not yet produced these training artifacts.

## Lyapunov Configuration Supplement (2026-09-12) <a href="#section-006" id="section-006"></a>

Static property heads only declare through L01/L08 that dynamic decrease is inapplicable; specified structure-optimization or real-dynamics branches may connect the remaining units, and denoising steps are not physical time. L01/L08 record applicability, assumptions, and evidence; see [44 Lyapunov Stability in Detail](44.md) for mathematics and unit interfaces. This is a design awaiting implementation, not a stability validation result.

## Mathematical Task Contract and Extension Priorities (2026-09-12) <a href="#section-007" id="section-007"></a>

Define objectives and data domains separately for structures, energies, forces, and experimental endpoints. Accurate energy-value fitting does not ensure accurate derivatives; validate using force labels or appropriate derivative norms. Multiple conformations should retain their conditional distribution or selection rule; structural outputs are not efficacy evidence.

Use [48 Mathematical Assessment](48.md) to distinguish representational, learning, and numerical solution capabilities; follow [49 Task Cards](49.md) by starting with fixed-structure baselines and then adding individual extensions supported by evidence. There is no need to first simulate the complete computation of other models.
