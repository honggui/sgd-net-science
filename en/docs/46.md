## 2. What Exactly Does the Prior–Posterior Comparison Compare? <a href="#section-002" id="section-002"></a>

Save the prediction `p⁻(y_t|history)` before new observations arrive; afterward, compute innovations or prediction scores using y_t for the same entity, time, and model version. If the model separately defines a state-update distribution, an estimated posterior q⁺ may be obtained. Differences between the model's own prior and posterior measure update magnitude, not directly true errors; both may be wrong together.

Record valid observation innovations, prediction NLL/calibration, prior/updated-distribution differences (only in comparable probability spaces), constraint violations, recurrence frequencies, out-of-domain indications, data quality, and actual task failures together. An h corrected by an ordinary SSM is not automatically a Bayesian posterior; without a probability model, use the term “prediction–observation discrepancy.”

First check identities/units/clocks, noise, missing observations, and label quality. One large error does not automatically trigger splitting; consider growth only for persistent, reproducible errors with evidence of insufficient capacity. Otherwise calibrate, add observations, call higher-fidelity tools, or retain unknown status. Validate drift thresholds on actual data distributions rather than unconditionally transferring online-tree theoretical bounds to correlated neural trajectories.

## 3. Eight Internal Evolution Units <a href="#section-003" id="section-003"></a>

| Subunit | Basic parent units | Input → output |
|---|---|---|
| EV01 Prediction snapshots and innovations | F01/F08, D05 | Pre-observation predictions + later outcomes → paired error signals |
| EV02 Persistence/drift diagnosis | F01/F02 | Multiwindow errors and QC → candidate causes, confidence, and triggering conditions |
| EV03 Structural candidate generation | F03/F04 | Causes and resources → candidates such as splitting/widening/edge addition/experts/no change |
| EV04 Parameter and state migration | F05/F06/F08, G06 | Old structure → candidate new parameters, memory, masks, and optimizer states |
| EV05 Local training and competition | G01/G03/G05 | New outcomes and old-task replay → parent-model/candidate performance comparisons |
| EV06 Stability and equivariance review | C07/C08, L03/L06/L08, G07 | Candidate structures → structural, numerical, symmetry, and task evidence |
| EV07 Persistent acceptance and monitoring | G06, H04/H08 | Candidates passing predefined gates → new versions and degradation monitoring |
| EV08 Pruning/merging/distillation | F04, G05/G06 | Long-term usage and effect records → compressed versions or candidate reversals |

EV units are internal workflow units and are not double-counted as new top-level network layers. The complete research path must define EV01–EV08; evidence determines whether any candidate is accepted.

## 4. Growth Targets Must Be Concrete <a href="#section-004" id="section-004"></a>

| Growth action | Object actually changed | Initialization, retention, and constraints |
|---|---|---|
| Leaf splitting | Feature-space partitions and local experts for nodes/subgraphs | New leaves first copy parent experts, with zero-output residual heads; train differentiation afterward |
| Multitree ensembles | Independent routing/expert members | Create diversity through resampling or feature subsets and record cost; duplicating identical models is not an ensemble |
| Graph representation refinement | Computational nodes/edges and resolution | P/Q migrate h/z at all layers; handle mass, coordinates, and boundaries according to domain rules |
| Learned relation addition/removal | Typed candidate message edges | Edge gates may start at zero; separate from chemical bonds/embodiment constraints that cannot be arbitrarily changed |
| Hidden-state widening | s or feature capacity d, local adapter capacity | Initialize new dimensions and cross-connections to zero; preserve old paths, then train progressively |
| Expert-block addition | Local GNN/EGNN/SSM experts or residual blocks | Compatible types and input/output; initialize new blocks approximately as identity/zero residual |

Zero initialization only reduces discontinuity; it is not a universal function-preservation proof. LayerNorm dimensions, softmax, gating denominators, random states, solvers, and downstream readouts may change with widening and require checks. Create optimizer slots for new parameters and copy old slots according to mappings; old-shape checkpoints cannot be loaded directly into new shapes.

The “birth” of graph nodes representing newly identified entities in data differs from computational representation splitting. Capacity optimization cannot arbitrarily change real counts of atoms, fingers, or cells. Equivariant tree splits should prefer invariants under the corresponding group; routing by absolute x-axis thresholds does not justify claims of rotational equivariance.

## 5. Four Time Scales Form Continuous Evolution <a href="#section-005" id="section-005"></a>

**Event level:** Update memory and error signals with new observations; this is online state adaptation, not parameter learning.

**Within-task level:** Adjust computational trees, routing, or graph resolution within reserved capacity, using frozen weights and bounded budgets; this is usually temporary inference adaptation.

**Session/window level:** Train bounded adapters, tree thresholds, or new experts from real feedback in candidate copies isolated from critical execution; predefined validation conditions may permit automatic acceptance and persistent storage. This is part of online continual learning and does not require human approval for every update, but cannot bypass prescribed validation or alter hard constraints.

**Generational level:** For backbone widening, cross-domain merging, and major structural changes, use more extensive replay, independent validation, and recompilation. Release and monitor new versions after passing; distill effective slow paths into fast paths and prune low-value branches. Offline consolidation supplements online evolution rather than being its only form.

Explicitly distinguish learnable calibration/alert parameters from foundational safety rules that the task model cannot freely lower. “Risk thresholds can change online” in the older 27 can only be interpreted within declared applicability ranges, not as an interface for relaxing hard constraints to increase pass rates.

## 6. Acceptance Criteria and Self-Evaluation Bias <a href="#section-006" id="section-006"></a>

Compare structural candidates using

$$
S=\widehat{\Delta Q}_{new}-\lambda_C\Delta Cost-\lambda_F Forgetting-\lambda_V Violations.
$$

This is only a candidate-ranking metric. Formal acceptance still requires old-task performance within predefined tolerances, benefits on independent new data, and passing calibration/equivariance/stability/resource checks; weighted scores cannot offset hard violations. Without ground truth in a new domain, state updates or self-supervised candidate research are possible, but improved capabilities cannot be claimed.

Use prequential evaluation that predicts before revealing labels, delayed-label alignment, old-task replay, and independent shadow comparisons. Repeated use of the same held-out set overfits it; retain subsequent time periods or rotate validation, recording the number of model-selection rounds. Count model-generated pseudo-labels separately from real outcomes to avoid a self-approval loop.

Growth has limits and must also permit no growth, merging, and rollback. Put triggering thresholds, evidence windows, maximum leaf counts, state widths, update frequencies, resources, and release tolerances in task configurations; no data currently exist, so do not fabricate claims that these values are already optimal.

## 7. A Unified Path with Implicit Solves and Lyapunov Conditions <a href="#section-007" id="section-007"></a>

```text
Pre-observation prediction snapshot → Real outcome → Multiwindow cause diagnosis
  → Bounded explicit/implicit recomputation or additional observations
  → If evidence of insufficient capacity remains, propose tree/graph/state/expert candidates
  → Parameter and state migration → Local training and parent–child competition
  → Equivariance, stability, old-task, out-of-domain, and resource validation
  → Automatically accept as a new version or discard the candidate
  → Runtime monitoring → Pruning, merging, distillation, and the next feedback round
```

Slow numerical root finding does not necessarily imply insufficient capacity and must not automatically trigger growth; growth may also worsen equation conditioning. [45 Implicit Solves](45.md) requires graphs and dimensions to remain fixed within a solve; rebuild residual operators across versions. L06 checks V comparability across topologies and switching budgets; tolerances cannot accumulate without bound.

## 8. Domain Applications and Validation Plan <a href="#section-008" id="section-008"></a>

Dexterous hands may grow embodiment-conditioned local experts and contact computational representations; molecules/materials may grow local residual experts or valid coarse/fine representations; cell and signaling models may grow conditional experts without automatically declaring new causal edges; neurobehavioral models may add session adapters and interaction-mode experts. Each domain uses its own labels, symmetry groups, and batch/subject isolation.

Experimental controls compare fixed models, memory-only updates, fixed-capacity continual learning, temporary refinement only, and full persistent growth. Report new-task learning, old-task forgetting, capacity curves, benefits per acceptance, false growth triggers, and costs separately. Only when persistent versions provide reproducible benefits on subsequent independent real data can validated continuous evolution be claimed; increasing branch counts alone does not improve intelligence.
