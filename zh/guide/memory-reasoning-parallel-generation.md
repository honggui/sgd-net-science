# 记忆—推理巩固闭环与并行生成设计

> 2026-09-13。将讨论结论落实为现有组件的组合合同和实验计划。本文不新增顶层组件 ID，不宣称实现、训练或加速结果；“知行合一”等类比只帮助解释，不构成认知等价或约束保证。

## 1. 设计判断与适用范围 <a id="section-001"></a>

动态树、图表示生长、持久历史、递归状态、回放与蒸馏可以共同构成“经历—记忆—推理—巩固”闭环。潜在收益是局部适应、关系化经历检索、将反复有效的慢推理转为快路径；当前没有实验证明这些收益已获得或优于 Transformer。

生成方式由任务定义，不固定为逐 token 自回归。E04 已有动作块输出，E07 已有连续流匹配实例，E08 可按实体/查询输出；离散扩散语言生成仍需专门的训练与采样合同。详见[已有生成头](../docs/chapters/36/section-21.md)、[持续演化](../docs/46.md)和[图记忆基础](mathematical-computing-foundation.md)。

## 2. 从经历到可复用能力的闭环 <a id="section-002"></a>

| 阶段 | 现有责任单元 | 写入或改变的对象 | 保留条件 |
|---|---|---|---|
| 记录经历 | C01/C08、U03、H02/H08 | 事件、关系、来源、时间、可寻址记录 | 原始证据与预测/想象分别标记 |
| 更新当前估计 | D04/D05、EV01 | 节点/边状态与预测误差 | 先保存观测前预测；不把更新幅度当真实误差 |
| 诊断与分工 | EV02/EV03、F03/F04 | 路由、局部专家、计算细化候选 | 区分缺数据、噪声、漂移、求解和容量不足 |
| 候选学习 | EV04/EV05、G05/G06 | 候选参数、结构、状态及优化器 | 新数据与旧任务回放；活动版本隔离 |
| 接纳与监测 | EV06/EV07、L、H04/H08 | 完整新版本及适用范围 | 独立证据、约束、旧任务与预算检查 |
| 整理与巩固 | EV08、G05/G06 | 合并、剪枝、蒸馏后的快路径 | 稀有情形、边界、旧任务及新数据重新验证 |

事件级状态更新、任务内临时路由、窗口级参数学习与代际巩固使用不同时间尺度。不能把所有层次都称为无条件实时更新。原始观测若有错误，以带来源的更正记录修订；不能为了符合新模型而覆写历史证据。

增加计算节点不等于增加真实实体；剪除专家不等于删除对应经历。数据保留/删除策略与模型压缩策略分别定义。蒸馏拟合教师行为，教师本身可能有误；应继续对真实结果、长尾情形和领域约束验收。

慢路径到快路径的一种候选目标为：

$$
\mathcal L_{fast}=\lambda_d\,\mathbb E_{q\sim D_{replay}}d(F_\phi(q),T_\nu(q))
+\lambda_y\mathcal L_{observed}+\lambda_r\mathcal L_{retention}.
$$

教师 T 的版本 ν、回放分布、距离 d、权重及观测标签需登记；该式不是约束保证。少数危险或罕见错误不能被平均损失掩盖。快路径超出验证范围或不确定时，可切回检索、专家竞争或求解路径。用同任务质量下的成本下降评价“内化”，不以剪枝数量或自评分数评价。

## 3. 约束如何与记忆和行动协调 <a id="section-003"></a>

可将适用约束写入类型、等变表示、训练目标和候选生成，并让记忆保存条件与例外；L/H04 对需要的结果执行独立检查。学到的规律是近似模型，不能替代所有执行条件。Lyapunov 条件只在相应系统、域和切换假设下生效；蒸馏或生长后需重新检查适用性。

这种协调可理解为“知道什么、依据什么、何时适用、如何执行”的一致性。它不意味着模型拥有人的体验，也不意味着只要训练充分就永远不会违反约束。共同版本闭包、错误反馈和可检查边界比类比更重要。

## 4. 区分自回归、DiT 与扩散语言生成 <a id="section-004"></a>

自回归解码按前缀逐步生成，但 Transformer 的层内张量计算和已知目标序列的训练并非全部串行。DiT 原始工作用 Transformer 作为图像潜空间扩散主干；它不等于将语言 Decoder 直接改为一次输出。[DiT](https://arxiv.org/abs/2212.09748)

LLaDA 采用离散掩码与逆向生成；Dream 7B 通过迭代去噪并行修正序列。共同特点是每轮可处理多个位置，轮次之间仍有依赖；并行不意味着输出位置独立，也不自动意味着少于 token 数的轮次或更低延迟。[LLaDA](https://arxiv.org/abs/2502.09992)、[Dream 7B](https://arxiv.org/abs/2508.15487)

本项目可选择直接联合读出、动作块、连续流/扩散、离散掩码迭代或分块自回归。不同选择要单独训练、登记输出依赖和验收；移除因果掩码不等于完成扩散模型转换。

## 5. SGD-Net 并行生成配置与缺口 <a id="section-005"></a>

| 配置 | 归属 | 已有基础 | 需补齐 |
|---|---|---|---|
| 多实体/多查询直接读出 | E03/E05/E06/E08 | 节点、属性、场查询头 | 联合一致性、分批语义及实际并行度 |
| 多步动作块 | E04、H04/H05 | 固定跨度动作候选 | 耦合约束、执行前缀、反馈后重规划 |
| 连续联合生成 | E07、U06、D/U02 | 流匹配数学实例 | 噪声/路径、步长/求解器、约束、收敛与预算 |
| 离散掩码生成 | U06、E07/E08、B02/U02 | 生成扩展与序列/关系接口 | 损坏过程、损失权重、词表、长度/EOS、采样与重掩码规则 |
| 局部自适应修正 | F03/F04、H03/H07 | 选择候选及局部计算的机制 | 活动集合、依赖传播、缓存失效、全局协调频率 |

离散路径可以从条件掩码预测基线开始：

$$
\tilde y\sim q_\tau(\tilde y\mid y),\qquad
\mathcal L_{mask}=\mathbb E\!\left[\sum_{i\in\mathcal I(\tilde y)}w(\tau,i)
\bigl(-\log p_\theta(y_i\mid\tilde y,c,\tau)\bigr)\right].
$$

该式是待实现训练模板，不自动等于某一扩散模型的精确似然或下界。需定义 q、掩码集合 I、时间采样和权重；若声称复现某篇论文，应采用并检验其完整过程。不能用连续实数流匹配 ODE 直接替代离散 token 生成。

推理配置应登记 output_schema、length_policy、noise_or_mask_schedule、update_set、round_limit、stop_rule、rng_state、dependency_policy、precision、budget、validation_profile；这些是建议的软件字段，不新增硬件 ABI。

## 6. 并行轮次、记忆与局部修正的执行合同 <a id="section-006"></a>

一轮候选更新可写为：

$$
Y^{k+1}=\operatorname{Update}_{\mathcal A_k}
\left(Y^k,F_\theta(Y^k,c,\tau_k;\mathcal M^{snapshot})\right).
$$

同一轮读取冻结的 Yk 与记忆快照，产生下一缓冲区；这是一种同步更新配置。若采用异步/原位更新，必须另定义语义，不能依线程执行顺序偶然决定模型。物理时间 t、生成时间 τ、修正轮次 k 和版本 ν 分开；去噪一轮不得自动推进 D04 的物理状态，候选结果不得写入真实经历。

只更新困难区域是候选优化，不能假定冻结其他位置就保持全局一致。图路径需扩展到受影响邻域或周期性全局检查；密集注意力中改变一个位置可能影响全部位置。双向生成通常不能原封不动复用自回归 KV 缓存；缓存有效性由依赖决定，近似复用另计质量误差。

一次生成内默认固定模型、图模式与记忆版本。EV 学习在候选域执行，结果供下一次请求或声明的边界使用；如要在轮次间改变图结构，需显式状态迁移、重新验证并登记为不同配置。多候选可以并行计算，但外部动作仍按允许前缀、时序与反馈提交。

## 7. 效率与验收计划 <a id="section-007"></a>

$$
t_{AR}\approx\sum_{i=1}^{T}t_{step,i},\qquad
t_{parallel}\approx\sum_{k=1}^{K}t_{round,k}+t_{schedule}+t_{check}.
$$

每轮完整输出的成本不等于一次增量解码，T/K 不是自动加速比。必须比较同质量、同条件、同硬件下的完成时间、首个可用结果时间、内存、能耗与批量吞吐；并计入检索、重掩码、全局协调、失败重算和蒸馏训练成本。

| 实验 | 对照与关键测量 |
|---|---|
| 记忆修正与持续学习 | 仅状态更新、固定容量训练、持久生长；新旧任务、延迟标签、长尾与漂移 |
| 巩固与剪枝 | 原慢路径、蒸馏快路径、快慢混合；独立数据误差、约束、回退率和总成本 |
| 并行生成 | 自回归、直接块输出、全局迭代、局部迭代；同质量延迟/内存曲线 |
| 缓存与同步 | 全量重算对照；改变单位置、随机执行顺序、版本切换与缺失观测 |
| 闭环执行 | 动作块预测与实际执行分开；前缀有效性、后续反馈及重规划 |

上述为未执行的实验计划。芯片/运行时需求是可组合的批量计算、分段归约、活动掩码、双缓冲、依赖/版本管理和成本计量。动态小集合可能降低矩阵利用率；是否提供专用融合路径应由实际轨迹决定，不新增“知行合一”或“扩散智能”模型名指令。
