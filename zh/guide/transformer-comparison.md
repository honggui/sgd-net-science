# SGD-Net 与 Transformer：算子覆盖、架构差异与补齐建议

> 2026-09-13。依据当前公开研究架构审查；“已定义”表示文档中的数学或接口定义，不表示代码、训练权重、芯片实现或性能已验证。本文新增比较与候选规格，不改变 72 个顶层组件，也不将 U 系列可选项改为默认必选项。

## 1. 结论与证据范围 <a id="section-001"></a>

SGD-Net 需要 Transformer 使用的许多基础算子：线性投影、非线性、残差、归一化、掩码、归约和张量布局操作。它们也是图消息、状态门控与领域读出的基础。全局或跨模态注意力、可寻址历史则按任务需要启用。

当前最准确的判断是：**基础计算已有较具体定义，完整注意力与缓存已有扩展归属，现代 Transformer 变体的执行合同尚不完整，端到端兼容没有验证。** 不能从“可调用预训练编码器”推导“内部已实现 Transformer”。

项目证据包括 [D01—D08 内核](../docs/chapters/36/section-20.md)、[B 组编码与融合](../docs/chapters/36/section-18.md)、[U 扩展](../docs/chapters/36/section-26.md)、[47 通用性边界](../docs/47.md)及[组件登记](../architecture/README.md)。下表使用三种设计状态：A 为已有具体数学定义，B 为已列入可选能力，C 为仍需补充的具体合同；三者都不代表已实现。

比较基线是标准密集 Transformer，并单独标明 RMSNorm、SwiGLU、RoPE、GQA 等变体；不把这些变体、MoE 或推理缓存统称为所有 Transformer 的必备组件。[Transformer 原论文](https://arxiv.org/abs/1706.03762)

## 2. 算子逐项对照 <a id="section-002"></a>

| 算子或功能 | SGD-Net 的用途与归属 | 当前设计状态和缺口 |
|---|---|---|
| Embedding、查表与输入投影 | B02/B03：文本、残基、元素与实体类型编码 | A；词表、分词、未知类型和输入映射仍须按任务固定 |
| Linear / GEMM、偏置 | B 组、D02 消息 MLP、D04 门控投影、D06 FFN、E 组输出头 | A；几何向量只能使用相容的通道混合与偏置规则 |
| ReLU / GELU / SiLU / 门控乘法 | D02 的参考路径为 Linear–SiLU–Linear；D04/D05 使用门控 | A 为已有 SiLU/门控；U04 为 B；指定 GELU 近似和 SwiGLU 组合为 C |
| FFN 与残差加法 | D06 节点残差 FFN | A；其输入包含消息/状态，不等于原 Transformer 逐 token FFN 的同权重替身 |
| LayerNorm / RMSNorm | D01 标量 LayerNorm；向量使用不变范数 | LayerNorm 为 A；RMSNorm、epsilon、统计轴、Pre/Post-Norm 组合为 C，归 U04/D01 |
| Q/K/V 投影、分头与合头 | U02，关联 B02/B07、D02/D03 | B；需固定头数、维数、布局、输出投影与权重映射 |
| QK 点积、缩放、行 Softmax、AV | U02 关系计算；可用于全局实体交互或跨模态查询 | B；D03 默认 sum/mean 不等价；B07 模态门控中的 Softmax 也不是完整注意力 |
| 因果、padding、跨模态掩码 | A 组有效性、B02/B07、U02 可见性 | A/B；广播轴、布尔含义、全屏蔽行、未来信息隔离需形成统一 C 合同 |
| 序列位置编码 / RoPE | B02 已定义位置与物理时间分离；U02 顺序能力 | 一般位置为 A/B；RoPE 的旋转维度、频率、位置偏移及缩放为 C |
| Cross-attention | B07 可选融合，U02 提供关系操作 | B；Q 来自查询，K/V 来自条件源，不能假设两者长度一致 |
| KV cache、增量追加、历史读取 | U03，关联 D04/F08/H02/H07 | B；缓存有效长度、批次重排、版本隔离和失效规则为 C；不是 D04 的递归状态 |
| GQA / MQA | U02 的头映射与 U03 的缓存布局 | C；多查询头共享 KV 头须显式定义，不能仅减少张量宽度 |
| token logits、log-softmax、交叉熵、采样 | E08/U06/G01/G03 的语言或离散序列任务配置 | B；E08 通用读出不等于完整 LM head，需词表投影、标签位移、忽略掩码和采样策略 |
| Dropout、反向传播、精度与随机状态 | D06 默认 dropout=0；G 组训练、U07/U08 符合性 | 已有训练设计；具体随机路径、梯度与推理关闭规则为 C |
| reshape、transpose、gather、scatter、分段归约 | U01/U04/H07；图索引、分头、token/实体映射 | 已有用途与扩展归属；stride、重复索引、分段边界及布局转换开销为 C |
| FlashAttention 式分块执行 | U02 的候选后端与 H07 调度 | C；属于精确注意力的 IO 优化，不是新增学习机制，也没有本项目内核或速度结果 |

LayerNorm 与 RMSNorm 不是同一操作：后者不执行均值中心化，不能无条件替换已有权重所用的归一化。[RMSNorm](https://arxiv.org/abs/1910.07467) SiLU 本身也不是 SwiGLU；一种无偏置 SwiGLU FFN 为：

$$
\operatorname{FFN}_{\mathrm{SwiGLU}}(H)=\bigl(\operatorname{SiLU}(HW_g)\odot HW_u\bigr)W_d.
$$

其两条输入投影、逐元素乘法和输出投影必须一起定义，隐藏宽度也要计入预算。[GLU Variants](https://arxiv.org/abs/2002.05202)

## 3. 为什么图聚合不自动等于注意力 <a id="section-003"></a>

对一个头，令 Q 的长度为 Tq、K/V 的长度为 Tk：

$$
Q=H_qW_Q,\quad K=H_kW_K,\quad V=H_kW_V,
$$
$$
S_{ij}=q_i^Tk_j/\sqrt{d_k}+b_{ij}+M_{ij},\quad
A_{ij}=\frac{\exp(S_{ij}-m_i)}{\sum_{r\in\mathcal V_i}\exp(S_{ir}-m_i)},\quad
Y_i=\sum_{j\in\mathcal V_i}A_{ij}v_j.
$$

这里有效键集合为 V_i，m_i 是有效分数的行最大值，M 为允许位置 0、禁止位置负无穷的加性掩码，b 为可选关系偏置。上式只适用于非空有效集合；全屏蔽行必须显式报错或走已声明的零输出路径，不能执行无定义的归一化。多头结果合并后再投影。[PyTorch 多头注意力](https://docs.pytorch.org/docs/2.14/generated/torch.nn.MultiheadAttention.html)

本项目的对应构造是：D02/U02 产生关系分数和值，D03/U02 执行按查询节点、按头的分段最大值/指数和/加权归约。若邻域不是全部允许的键，得到的是选定稀疏注意力，不能声称与密集注意力相同。

一个反例即可看出差异：同一查询对应两个标量值 0 和 2。mean 固定得到 1；若注意力权重为 0.9 和 0.1，则输出 0.2，且换一个查询可以得到另一组权重。缺少查询相关分数与行归一化，增加普通 sum/mean 层数不能使“该算子”自动成为注意力。

应在适配层统一掩码约定：PyTorch 的 SDPA 布尔 True 表示允许参与，而 MultiheadAttention 的布尔屏蔽掩码 True 表示禁止；不能直接传递而不转换。推理时也应显式设置 SDPA 的 dropout 概率为零。[SDPA 接口](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)

## 4. 架构层面的能力与代价 <a id="section-004"></a>

| 维度 | 标准密集 Transformer | SGD-Net 当前研究设计 |
|---|---|---|
| 信息交互 | 通过查询相关注意力读取允许的 token | 默认图消息；U02 可添加全局/稀疏注意力 |
| 时间记忆 | 自回归推理常保留历史 K/V；也可重算历史 | D04 为按实体递归状态；U03 按需保存可寻址历史 |
| 几何先验 | 普通 token 注意力没有自动的物理旋转/平移等变保证 | D07 在类型、图与群作用相容时具有 E(n) 等变结构；编码器/读出仍需相容 |
| 物理约束 | 基本块不自带守恒或稳定性保证，可以额外构建 | L/IM/领域头提供条件化稳定性、隐式求解与约束接口，仍须验证 |
| 结构适应 | 基本块通常固定；其他研究可引入路由、剪枝和记忆 | F/EV 设计了局部细化、持久生长和迁移；收益尚未实证 |
| 函数与任务偏好 | 灵活的内容寻址有利于跨位置关联；效果依赖训练与容量 | 显式关系、状态和对称性可形成任务先验；错误先验也会限制表达 |
| 实证状态 | 原论文及后续工作提供各自任务证据 | 当前发布是设计与验证计划，不能据组件数量宣称优于 Transformer |

以下为本项目的成本推导，不是性能测量。单层标准密集注意力取 T 个 token、总头宽 d，交互工作量约 O(T²d)，投影约 O(Td²)，FFN 约 O(Tdd_ff)。FlashAttention 通过分块减少中间注意力矩阵的存储和访存；密集交互算术仍是二次量级。[FlashAttention](https://arxiv.org/abs/2205.14135)

SGD 的 N 节点、E 边若每边使用宽 d 的稠密两层消息 MLP，成本可能为 O(Ed²)，而投影后稀疏点积注意力的关系部分可为 O(Ed)，两者不能混淆。D04 的状态更新为 O(Ns)，但其投影、构图、几何、求解迭代、候选轨迹与训练状态必须另计。[现有成本边界](../docs/chapters/36/section-29.md)

对等宽 K/V 的常规解码缓存，原始缓存字节为：

$$
B_{KV}=2LBT H_{kv}d_h b,\qquad B_z=LB N s b.
$$

L 为层数，B 为批量，b 为每元素字节，Hkv 为 KV 头数，dh 为头宽；第二式仅为本项目简化 z 状态，不含其他内存。固定实体数下 z 可不随历史长度增长，但这是压缩记忆，不保证精确回读任意历史。GQA 减少 KV 头数，却仍需计算查询头的注意力。[GQA](https://arxiv.org/abs/2305.13245)

例如 L=24、B=1、T=4096、Hkv=8、dh=64、b=2，原始 KV 为 192 MiB；若 N=128、s=128，相应 z 为 0.75 MiB。这个算术例子没有对齐任务能力、其余状态或质量，不能当作等效模型的 256 倍内存优势。

## 5. 建议怎样融合，而非全面替换 <a id="section-005"></a>

沿用“能力优先”共识：保留 D02/D03 的局部结构计算、D04 的时间状态，在存在跨实体长程关系或跨模态查询瓶颈时加入 U02；只有需要精确历史查询或增量自回归时加入 U03。文本与蛋白序列可复用 B02 编码器，但必须分开报告外部模型贡献。

对于物理 AI，可构造一个待验证的等变注意力分支：

$$
\alpha_{ij}=\operatorname{softmax}_{j\in\mathcal N(i)}
f_\theta(h_i,h_j,\|x_i-x_j\|^2,a_{ij}),\qquad
\Delta x_i=\sum_j\alpha_{ij}c_{ij}(x_i-x_j).
$$

只有 h、a、c 和注意力分数在所选群作用下不变，且邻域构造相容，标量权重乘相对向量的更新才保持相应 E(n) 等变性。此推导沿用等变消息构造原则，不宣称是本项目独创，也不等于已经训练有效。[EGNN](https://proceedings.mlr.press/v139/satorras21a.html)

序列 RoPE 作用于 Q/K 特征对以表达位置关系；它不是物理空间 E(n) 等变约束，也不能用它替代 D07。序列位置、物理时间与空间坐标应保持不同类型。[RoFormer](https://arxiv.org/abs/2104.09864)

优先补齐三个配置，而非新增一串顶层 ID：

1. **基础算子配置**：D01/D02/D06/U04 明确激活、归一化、偏置、残差顺序和张量轴；匹配目标模型时区分 Pre-Norm 与 Post-Norm。[EncoderLayer 配置](https://docs.pytorch.org/docs/2.14/generated/torch.nn.TransformerEncoderLayer.html)
2. **关系计算配置**：U02 明确 QKV、头布局、Softmax 轴、掩码、位置、空行语义及局部/全局边集合。
3. **增量记忆配置**：U03 明确模型/层/会话版本、位置偏移、有效长度、追加、重排和失效；权重或位置规则改变时，旧缓存不得默认继续使用。

混合模型可以在不变标量流上融合局部消息、状态与全局关系，向量流使用类型相容读出。混合后应重新训练与验证，不能假定继承原 Transformer 权重的输出。若任务要求精确迁移 Transformer，则按 U08 走独立兼容配置，旁路会改变输出的额外几何/状态/投影操作。

## 6. 验证与硬件含义 <a id="section-006"></a>

这次文档补充没有实现或运行以下模型实验；它们是判定“支持”所需的后续验收：

| 验收 | 要排除的错误 |
|---|---|
| 同参数单头/多头前向及梯度对照 | 缩放、分头、转置、归一化轴或输出投影错误 |
| 更改未来 token、增加 padding、全屏蔽行 | 未来泄漏、padding 污染、NaN 或未声明的空行行为 |
| 全序列计算与逐 token 缓存解码对照 | 位置偏移、重复追加、会话混用、缓存失效遗漏 |
| GQA 头映射、Cross-attention 不等长输入 | 错误广播和把自注意力布局套到跨模态输入 |
| 旋转/平移/重标号差分 | 注意力输入、邻域或向量输出破坏类型与等变条件 |
| 固定图+SSM、加 U02、再加 U03 的消融 | 无法区分能力增益来自注意力、记忆还是额外预算 |

容差按 dtype、序列长度和后端登记，比较输出、梯度、缓存状态和峰值内存。质量测试应使用同数据划分、可观测信息和明确的训练/推理预算；同时报告失败率和端到端延迟，不能只报告 GEMM 吞吐。

对 Aegis-X 的建议属于工作负载要求，不是已完成的芯片 Spec 审计：[现有映射](../docs/chapters/36/section-09.md)中的矩阵单元继续服务投影/FFN/QK/AV；Vector/归约承担 exp、max/sum、rsqrt、激活与掩码；Sparse/索引和 DMA 处理图关系、布局及状态搬运。分块注意力和 KV 分页是否值得专门优化，应由实际负载轨迹决定。不要因 Transformer 流行就强制所有 SGD 配置携带 KV cache，也不要因保留 SSM 就省掉必要的矩阵和归约能力。

**研究优先级：先做可靠的共同算子与 U02 关系配置，再按任务证据启用 U03；以质量—成本和约束一致性评价混合架构。** 这延续 [49 能力优先路线](../docs/49.md)，没有把完整 Transformer 模拟重新设成项目总目标。
